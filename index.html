Un guide concret, et appliqué, pour atteindre le confort de lecture de Medium et Substack sur desktop comme sur mobile.

IdeasFont · Lecture 7 min · 3 mai 2026

La plupart des sites de contenu négligent un détail invisible mais décisif : le rythme typographique. Trop d'espace, pas assez, des titres mous, des paragraphes tassés, et le lecteur abandonne sans savoir pourquoi. Ce document applique, ligne par ligne, ce qu'on devrait faire.

Pourquoi 19 / 1.65 / 740px est le standard d'or

Trois nombres suffisent à cadrer 80 % du travail : 19 px de font-size, 1.65 de line-height, ~740 px de largeur max. C'est ce que pratiquent Substack, le blog de Stripe, celui de Linear, Stratechery et la quasi-totalité des produits dont la lecture est le cœur. Pas une mode : la résultante de décennies de recherche en lisibilité, depuis le Bringhurst jusqu'aux études d'eye-tracking modernes.

Sur mobile, on reste sur du 16 px / 1.6 / pleine largeur avec 20 px de padding latéral. C'est le défaut système iOS, le seuil au-dessous duquel iOS déclenche un zoom involontaire sur les input, et le confort suffisant pour des cards ou des paragraphes courts. Inutile de pousser plus haut sauf si l'app est 100 % long-form.

Le piège du line-height uniforme

L'erreur la plus répandue, visible sur la plupart des sites de listing comme Ideas.xyz, c'est d'appliquer un line-height: 1.5 partout. Résultat : les titres flottent (mou), les paragraphes étouffent (fatigant). La règle est simple et inverse :

Le système complet, en CSS

Plutôt que des media queries en cascade, on utilise clamp() pour interpoler en continu entre mobile et desktop. Le code suivant suffit à cadrer un site de lecture entier : 

:root {
  --fs-body: clamp(1.0625rem, 0.95rem + 0.36vw, 1.1875rem); /* 17 → 19 */
  --fs-h1:   clamp(2rem,      1.4rem + 3vw,    3.5rem);  /* 32 → 56 */
  --fs-h2:   clamp(1.625rem,  1.3rem + 1.6vw,  2.25rem); /* 26 → 36 */
  --fs-h3:   clamp(1.25rem,   1.1rem + 0.75vw, 1.625rem);/* 20 → 26 */
  --lh-body: 1.65;
  --measure: 68ch;
}

article p {
  font-size: var(--fs-body);
  line-height: var(--lh-body);
  max-width: var(--measure);
  margin-inline: auto;
  text-wrap: pretty;
}

article h1 {
  font-size: var(--fs-h1);
  line-height: 1.1;
  letter-spacing: -0.022em;
  text-wrap: balance;
}

Les détails qui font 80 % du résultat

  • text-wrap: balance sur les titres pour éviter l'orpheline en bout de ligne.
  • text-wrap: pretty sur les paragraphes pour équilibrer les deux dernières lignes.
  • Letter-spacing négatif (-0.018em à -0.028em) sur les gros titres : les polices sans-serif s'étirent au-dessus de 32 px et perdent en densité visuelle.
  • Pas de noir pur sur fond blanc pur. #1a1a1a sur #fafaf7 réduit la fatigue oculaire de 20 %.
  • Ponctuation suspendue avec hanging-punctuation: first last (Safari only pour l'instant, mais gracefully ignored ailleurs).
  • Marges entre paragraphes : 1.4em minimum, jamais le 1em par défaut. C'est la respiration qui rend la lecture agréable.

Ce n'est pas une question de goût. C'est une question de physique de l'œil et de cognition. La typo confortable n'est pas plus belle, elle est juste moins coûteuse à lire. Robert Bringhurst, The Elements of Typographic Style

Et pour Ideas.xyz spécifiquement ?

Le problème n'est pas le contenu, il est excellent. Le problème, c'est que chaque carte d'idée business est rendue en ~14 px / 1.4, ce qui force le lecteur à plisser les yeux et à lire ligne après ligne sans rythme. Cinq changements suffisent :

  1. Passer le body des cartes à 17 px / 1.6 (mobile) et 19 px / 1.65 (desktop).
  2. Limiter la largeur des cartes à 60–65ch (~580–620 px), pas plus.
  3. Augmenter l'espace inter-carte à 2rem minimum.
  4. Renforcer la hiérarchie : titre de carte en 22 px / 1.25 / 700, pas en 16 px / 600.
  5. Retirer le noir pur du body au profit d'un #1f2937 doux.

TL;DR à coller dans le brief

19 / 1.65 / 740px sur desktop. 17 / 1.6 / pleine largeur avec 20 px de padding sur mobile. clamp() pour interpoler entre les deux. text-wrap: balance sur les titres, pretty sur les paragraphes. Pas de noir pur. Une seule famille pour les titres, une autre pour le body, et c'est tout. Le reste, c'est de la cosmétique.
